# [APPT-001] 【測試】掛號基本功能

## 背景與動機

醫院目前掛號流程分散於多個系統，現場掛號、電話掛號與線上掛號的資料未能即時同步，導致重複掛號、診間叫號錯誤等問題頻繁發生。xHIS 掛號系統需建立統一的掛號作業核心，作為後續線上掛號、候診管理等進階功能的基礎。

## 目標

- 提供掛號人員完整的掛號、取消、改號操作介面
- 確保掛號資料即時同步至診間叫號與批價系統
- 支援健保身分驗證，降低人工核對錯誤率

## 非目標（Not In Scope）

- 線上/APP 掛號（另立 APPT-002）
- 診間叫號顯示系統（另立 APPT-003）
- 預約簡訊通知（另立 APPT-004）

## 使用者與情境

**目標使用者**：掛號櫃台人員

**使用情境**：
> 病患至掛號櫃台，掛號人員透過系統查詢門診班表，確認診別與醫師後完成掛號，並列印號單給病患。若病患需要取消或更改掛號，掛號人員可於系統內直接操作。

## 功能需求

### FR-01 查詢門診班表

**說明**：掛號人員可依日期、科別、醫師等條件查詢當日及未來 30 天的門診班表，包含每診可掛人數與剩餘號數。

**驗收條件**：
- [ ] 可依「日期」、「科別」、「醫師姓名」單一或組合條件查詢
- [ ] 班表顯示診別、主治醫師、看診時段、總號數、已掛號數、剩餘號數
- [ ] 已額滿診別以明顯視覺標示區隔，且無法選取掛號
- [ ] 查詢結果於 2 秒內呈現

### FR-02 新增掛號

**說明**：掛號人員選定門診班次後，輸入病患身分資料完成掛號，並產生掛號號次。

**驗收條件**：
- [ ] 支援以「健保卡讀卡機」或「手動輸入身分證號」兩種方式取得病患資料
- [ ] 系統自動查詢病歷號，若為新病患則提示建立病歷
- [ ] 掛號完成後即時產生號次，號次於同一診間當日不重複
- [ ] 掛號完成後可列印號單（格式包含：診別、醫師、看診時段、號次、候診人數）
- [ ] 同一病患同一診間當日不可重複掛號，重複時顯示警示並阻擋

### FR-03 取消掛號

**說明**：掛號人員可取消尚未報到的掛號，取消後號次釋回供其他病患使用。

**驗收條件**：
- [ ] 可依「病患姓名」、「身分證號」、「病歷號」或「掛號號次」查詢待取消掛號
- [ ] 取消前需顯示確認提示，包含病患姓名、診別、醫師、號次
- [ ] 取消成功後號次立即釋出，剩餘號數即時更新
- [ ] 已報到或已看診的掛號不可取消，操作時顯示明確錯誤原因

### FR-04 改號

**說明**：掛號人員可將病患掛號由原班次更改至同日或其他日期的指定班次。

**驗收條件**：
- [ ] 改號操作為「取消原掛號 + 新增掛號」的原子操作，需同時成功或同時失敗
- [ ] 改號完成後列印新號單，原號單自動作廢
- [ ] 已報到或已看診的掛號不可改號

### FR-05 病患報到

**說明**：掛號人員確認病患到達時進行報到，通知診間系統更新候診狀態。

**驗收條件**：
- [ ] 支援讀卡機刷健保卡自動報到
- [ ] 報到後候診狀態即時同步至 OPD 門診醫令系統
- [ ] 若病患未掛號直接報到，提示掛號人員先完成掛號

## 非功能需求

| 類型 | 需求描述 |
|------|----------|
| 效能 | 掛號、取消、改號等寫入操作須於 1 秒內完成；班表查詢須於 2 秒內回應 |
| 並發 | 同一診次剩餘號數須支援多工作站同時操作，避免超額掛號 |
| 安全性 | 所有操作須記錄操作人員帳號與時間戳，供稽核查詢 |
| 相容性 | 支援健保署規格健保卡讀卡機（HCE 規格） |
| 可用性 | 系統可用率需達 99.5% 以上（門診時段） |

## 技術備註

- 號次產生需使用資料庫層級的序列鎖（Row-level lock）避免並發衝突
- 健保卡讀卡需串接健保署 VPN 及 HCE API，需確認網路架構
- 掛號狀態變更需透過事件推送（WebSocket 或 SSE）即時同步至 OPD 模組
